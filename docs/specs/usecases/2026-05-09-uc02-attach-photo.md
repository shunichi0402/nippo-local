# Spec: UC02 写真を記録して文脈を残す

## 背景

テキストだけでは伝わりにくい状況を、写真で補足したい場面がある。
MVP では画像加工よりも、写真だけの単体記録と既存記録への添付を一貫して扱えることを重視する。

## 目的

- 写真だけの単体記録を作成できるようにする
- 既存の記録に写真を添付できるようにする
- 写真と説明文をセットで保存し、検索対象に含める
- 参照削除と実ファイル削除の挙動を分けて安全に扱う

## 対象ユーザー

- 現場写真や資料スクリーンショットを記録に残したいユーザー

## スコープ

### やること

- 写真アップロード
- 写真だけの単体記録作成
- 既存記録への写真添付
- 写真プレビュー
- 写真説明文の編集
- 写真の参照削除、実体削除

### やらないこと

- 画像編集、トリミング、自動補正
- OCR による自動テキスト抽出

## ユースケース

1. ユーザーは写真だけの記録を作成する
2. ユーザーはメモ作成時に写真を添付する
3. ユーザーは写真に説明文を付けて検索しやすくする
4. ユーザーは誤添付した写真の参照だけを外す
5. ユーザーは不要写真の実ファイルを削除する

## 仕様

### 入力

- 共通:
  - `authUserId` (必須): ログイン済みユーザー ID
  - `imageFile` (必須): `jpg/jpeg/png/webp`、1 ファイル 10MB 以内
  - `caption` (任意): 0-200 文字
- 写真だけの単体記録作成:
  - `title` (任意): 0-120 文字
  - `targetDate` (必須): `YYYY-MM-DD`
  - `tags` (任意): 0-10 件、各 1-30 文字
  - `category` (任意): 0-30 文字
  - `project` (任意): 0-50 文字
- 既存記録への添付:
  - `recordId` (必須): 添付先の記録 ID
- 削除:
  - `attachmentId` (必須)
  - `deleteMode` (必須): `detach_only` または `delete_file`

### 出力

- 添付成功時:
  - 記録 ID
  - 添付 ID (UUID v7)
  - 相対パス
  - 保存ファイル名 (`<attachmentId>.<ext>`)
  - 元ファイル名
  - MIME type
  - ファイルサイズ
  - キャプション
- 取得時:
  - プレビュー URL
  - 記録との紐付け情報

### バリデーション

- 許可拡張子以外は拒否
- 10MB 超過ファイルは拒否
- 添付 ID は UUID v7 で発行する
- 保存ファイル名は `<attachmentId>.<ext>` とし、元ファイル名を直接使わない
- 元ファイル名はメタデータとして保存する
- 写真だけの単体記録作成時は `targetDate` 必須
- 既存記録への添付時は `recordId` 必須
- `recordId` 未存在時は添付不可
- `recordId` が他ユーザー所有の場合は添付、更新、削除不可
- `caption` は 200 文字超過不可

### エラー時の動作

- 未ログイン状態では写真記録作成、添付、更新、削除を許可しない
- 他ユーザー所有レコードへの添付、更新、削除は 403 を返す
- アップロード失敗時は DB 更新を行わない
- 写真だけの単体記録作成失敗時は作成済み一時ファイルを削除
- DB 更新失敗時はアップロード済み一時ファイルを削除
- 実ファイル削除時に参照が残る場合は削除拒否
- エラー時は「再試行」「キャンセル」を提示

## 受け入れ条件

- [ ] 指定形式、指定サイズの写真を添付できる
- [ ] 写真だけの単体記録を作成できる
- [ ] 添付 ID と保存ファイル名が UUID v7 ベースで作成される
- [ ] 写真キャプションを保存、更新できる
- [ ] 参照削除と実ファイル削除を選択できる
- [ ] 実ファイル削除は参照整合性を壊さない
- [ ] 写真説明文が検索対象に含まれる
- [ ] 他ユーザー所有レコードへの添付、更新、削除が拒否される

## 確認方法

- 正常系: `jpg/png/webp` の写真単体記録作成、既存記録への添付、説明編集、プレビュー確認
- 異常系: 非対応拡張子、サイズ超過、存在しない `recordId`
- 保存名: 保存ファイル名が `<attachmentId>.<ext>` になり、元ファイル名がメタデータに残ることを確認
- 認可系: 他ユーザー所有 `recordId` への添付、更新、削除を検証
- 削除系: `detach_only` と `delete_file` の挙動差を確認

## 実装メモ

- API:
  - `POST /api/records/photo`: 写真だけの単体記録を作成し、同時に写真を 1 件添付する
  - `POST /api/records/:recordId/attachments`: 既存記録へ写真を添付する
  - `GET /api/attachments/:attachmentId/file`: 写真をプレビュー取得する
  - `PATCH /api/attachments/:attachmentId`: 写真説明文を更新する
  - `DELETE /api/attachments/:attachmentId`: `detach_only` または `delete_file` で削除する
- 保存先:
  - 実ファイルは `DATA_DIR/uploads/photos/<attachmentId>.<ext>` に保存する
  - DB には `photo_attachments` テーブルで相対パス、元ファイル名、MIME type、サイズ、説明文を保持する
- ID / ファイル名:
  - 添付 ID は UUID v7 形式で発行する
  - 保存ファイル名は元ファイル名を使わず `<attachmentId>.<ext>` にする
- 検索:
  - 記録検索の `keyword` は既存 FTS に加えて、紐付いた写真説明文も対象にする
- 認可:
  - UC07 統合前の暫定実装として `x-user-id` ヘッダーをユーザー ID とみなし、未指定時は `local-user` を使う
  - 記録所有者と異なるユーザーによる添付、説明更新、削除は 403 で拒否する
