# Spec: UC07 ログインとアカウント管理を行う

## 背景

記録とレポートを個人単位で安全に扱うため、認証と認可が必要になる。
初期運用を成立させるには、初回起動時の admin 作成と、以後のアカウント管理を明確に定義する必要がある。

## 目的

- email とパスワードでログインできるようにする
- 初回起動時に admin ユーザーを登録できるようにする
- 設定画面で複数アカウントを管理できるようにする
- admin/user の権限に応じて機能とデータ参照を制御する

## 対象ユーザー

- 初回セットアップを行う管理者
- 日常利用する一般ユーザー

## スコープ

### やること

- ログイン、ログアウト
- JWT ベースの認証トークン発行、検証、失効
- 初回 admin 登録フロー
- admin によるアカウント作成、更新、停止
- admin による初期パスワード設定、パスワード再設定
- 権限 `admin` と `user` の判定
- ユーザー単位のデータ参照制御
- アカウント管理イベントの監査ログ記録

### やらないこと

- SSO 連携
- 多要素認証
- パスワードリセットメール送信

## ユースケース

1. 初回起動時に管理者が admin アカウントを作成する
2. ユーザーが email とパスワードでログインする
3. admin が設定画面で user アカウントと初期パスワードを追加する
4. admin が既存アカウントの表示名、権限、状態を更新する
5. admin が必要に応じて user のパスワードを再設定する
6. admin が user アカウントを停止する
7. user は自分の記録とレポートだけを参照する

## 仕様

### 入力

- ログイン:
  - `email` (必須): RFC 準拠の形式
  - `password` (必須): 8-128 文字
- 初回 admin 登録:
  - `displayName` (必須): 1-50 文字
  - `email` (必須)
  - `password` (必須)
- アカウント登録/更新 (admin のみ):
  - `displayName` (必須)
  - `email` (必須)
  - `initialPassword` (新規作成時必須): 8-128 文字
  - `newPassword` (パスワード再設定時必須): 8-128 文字
  - `role` (必須): `admin` または `user`
  - `status` (必須): `active` または `suspended`

### 出力

- ログイン成功時:
  - JWT アクセストークン
  - トークン有効期限
  - ログインユーザー情報 (`id`, `email`, `displayName`, `role`)
- アカウント管理成功時:
  - 対象アカウント情報
  - 更新日時
  - 実行者 ID
- 認可エラー時:
  - 403 とエラー理由

### バリデーション

- email 重複登録は禁止
- パスワードは 8 文字以上を必須とし、文字種の組み合わせは必須にしない
- アカウント新規作成時は admin が初期パスワードを設定する
- パスワード再設定は admin のみ実行できる
- `role` は `admin/user` 以外を拒否
- `status` は `active/suspended` 以外を拒否
- suspended アカウントはログイン不可
- suspended アカウントの既存記録、日報、月報、添付ファイルは削除しない
- suspended アカウントを active に戻した場合は、同じ所有データを再び参照できる
- 初回 admin 登録はアカウント 0 件時のみ許可
- 認証が必要な API は Authorization ヘッダーの Bearer トークンを必須とする
- 期限切れ、改ざん、不正署名の JWT は拒否する

### エラー時の動作

- ログイン失敗時は汎用メッセージを返し、失敗理由を詳細表示しない
- 一定回数以上の連続失敗時は一時的に試行を制限する
- トークン期限切れ時は再ログインを促す
- ログアウト後のトークン利用は拒否する
- アカウント停止後は、停止前に発行済みのトークンも拒否する
- 認可エラー時は対象データの存在有無を漏らさない
- アカウント管理失敗時は監査ログに失敗イベントを記録する

### セキュリティ要件

- パスワードはハッシュ化して保存し、平文を保持しない
- パスワードは 8 文字未満を拒否する
- JWT は有効期限を持ち、明示ログアウトで失効できる
- JWT 署名鍵は設定値として管理し、リポジトリに平文で含めない
- admin 操作 (作成、更新、停止、権限変更) は全て監査ログ対象とする
- admin 操作によるパスワード再設定は監査ログ対象とする
- API 側で `ownerUserId` とログインユーザー ID を照合し、他者データを返さない

## 受け入れ条件

- [ ] email とパスワードでログインできる
- [ ] ログイン成功時に JWT アクセストークンと有効期限が返る
- [ ] Authorization ヘッダーの Bearer トークンで認証 API を利用できる
- [ ] 期限切れ、不正、ログアウト済みトークンが拒否される
- [ ] 初回起動時のみ admin 登録が可能で、2 回目以降は不可
- [ ] admin が設定画面で初期パスワード付きの複数アカウントを登録、更新、停止できる
- [ ] admin が user のパスワードを再設定できる
- [ ] suspended アカウントはログインできない
- [ ] suspended アカウントの既存データは削除されない
- [ ] suspended から active に戻した場合、同じ所有データを参照できる
- [ ] user はアカウント管理機能にアクセスできない
- [ ] user は他ユーザーのメモ、日報、月報を参照できない
- [ ] パスワードが平文で保存されない
- [ ] 8 文字未満のパスワードが拒否される

## 確認方法

- 正常系: 初回 admin 作成、ログイン、JWT を使った認証 API 呼び出し、admin による初期パスワード付きアカウント追加
- 異常系: email 重複、8 文字未満パスワード、不正 role、suspended ログイン、停止前トークンでのアクセス
- 停止系: suspended 化して既存データが保持されること、active 復帰後に参照できることを確認
- トークン系: 期限切れ JWT、不正署名 JWT、ログアウト後 JWT での API アクセス拒否を確認
- パスワード系: admin によるパスワード再設定、旧パスワードでのログイン失敗を確認
- 認可系: user 権限でアカウント管理 API と他者データ API へアクセス
- セキュリティ: 保存データに平文パスワードが存在しないことを確認
