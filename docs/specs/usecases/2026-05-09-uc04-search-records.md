# Spec: UC04 記録を検索して再利用する

## 背景

記録件数が増えると、後から必要な情報を見つけられないことが最大のロスになる。
MVP では高速性よりも、日付、タグ、種類、キーワードの確実な絞り込みを優先する。

## 目的

- 記録を再利用可能にする検索体験を提供する
- 日報/月報作成の候補選定を短時間で行えるようにする
- 検索条件の組み合わせを一貫したルールで定義する

## 対象ユーザー

- 日次、月次で過去記録を振り返るユーザー

## スコープ

### やること

- 条件検索 (日付、タグ、種類、キーワード)
- ソート、ページング
- 検索結果から詳細表示へ遷移

### やらないこと

- あいまい検索の高度ランキング
- 類義語展開、形態素解析
- ベクトル検索

## ユースケース

1. ユーザーは指定日または期間で記録を絞り込む
2. ユーザーはタグと種類を組み合わせて検索する
3. ユーザーはキーワードで本文や文字起こしを横断検索する
4. ユーザーは検索結果から元記録を開き、日報候補に追加する

## 仕様

### 入力

- `authUserId` (必須): ログイン済みユーザー ID
- `fromDate` (任意): `YYYY-MM-DD`
- `toDate` (任意): `YYYY-MM-DD`
- `tags` (任意): 複数指定可
- `types` (任意): `memo/photo/audio/transcript/daily_report/monthly_report`
- `keyword` (任意): 1-100 文字
- `sort` (任意): `targetDate_desc/targetDate_asc/updatedAt_desc`
- `page` (任意): 1 以上
- `pageSize` (任意): 1-100

### 出力

- `items`: 条件一致した記録配列
- `totalCount`: 総件数
- `page`, `pageSize`
- 各アイテムの最小表示情報:
  - `id`, `type`, `title`, `targetDate`, `tags`, `updatedAt`
  - 本文または文字起こしのスニペット (最大 120 文字)

`items` には `authUserId` が所有する記録のみ含める。

### バリデーション

- 未ログイン状態での検索実行を拒否
- `fromDate` > `toDate` は拒否
- `pageSize` は 100 を上限
- `keyword` が空白のみの場合は無効
- 未定義 `types` は拒否

### エラー時の動作

- 不正検索条件は 400 系エラーとし、理由を返す
- 他ユーザーの記録 ID を直接指定した場合は 404 または 403 を返す
- 検索処理失敗時は条件を維持したまま再試行可能にする
- タイムアウト時は条件を変えずに再検索ボタンを提示

## 受け入れ条件

- [ ] 日付範囲で絞り込みできる
- [ ] タグ、種類、キーワードの組み合わせ検索ができる
- [ ] 本文、写真キャプション、文字起こしが検索対象になる
- [ ] 検索結果から元記録を開ける
- [ ] 不正条件時に理由付きエラーが返る
- [ ] 他ユーザーの記録が検索結果に含まれない

## 確認方法

- テストデータを 30 件以上用意して条件検索を検証
- `fromDate > toDate` などのバリデーション異常を検証
- 結果の件数、ページング、並び順を確認
