# Spec: UC01 テキストメモを素早く記録する

## 背景

日々の作業中に発生する小さな気づきは、記録までに時間がかかると失われやすい。
MVP では、最小操作でメモを保存できることを最優先にする。

## 目的

- 1 分以内にテキストメモを作成して保存できるようにする
- 日報/月報へ再利用しやすいメタ情報を同時に付与できるようにする
- 作成後の修正や削除を安全に行えるようにする

## 対象ユーザー

- 作業中に短文メモを素早く残したいユーザー
- 後で検索、集計しやすい形で記録したいユーザー

## スコープ

### やること

- メモ新規作成
- メモ編集
- メモ削除
- 対象日、タグ、カテゴリ、関連プロジェクトの設定

### やらないこと

- メモの共同編集
- リッチテキスト専用エディタ機能
- 外部サービスへの自動投稿

## ユースケース

1. ユーザーはタイトルと本文を入力してメモを保存する
2. ユーザーは対象日とタグを追加して検索しやすくする
3. ユーザーは誤記を編集し、不要になったメモを削除する

## 仕様

### 入力

- `authUserId` (必須): ログイン済みユーザー ID
- `title` (任意): 0-120 文字
- `body` (必須): 1-10000 文字、Markdown 記法を許可
- `targetDate` (必須): `YYYY-MM-DD`
- `tags` (任意): 0-10 件、各 1-30 文字
- `category` (任意): 0-30 文字
- `project` (任意): 0-50 文字

### 出力

- 保存成功時:
  - レコード ID
  - 作成日時
  - 更新日時
  - 入力済みメタ情報
- 一覧表示:
  - タイトル、冒頭 120 文字、対象日、タグ、更新日時

### バリデーション

- 未ログイン状態では作成、編集、削除を許可しない
- `body` が空文字の場合は保存不可
- `targetDate` は日付形式不正を拒否
- `tags` は重複を除外して保存
- 文字数上限超過時はフィールドごとのエラーを返す
- UC07 接続前のローカル実装では `x-user-id` ヘッダーを暫定的な所有者 ID として扱い、未指定時は `local-user` を使う

### エラー時の動作

- 他ユーザー所有レコードへの更新、削除は 403 を返す
- 保存失敗時は入力値をフォームに保持
- 永続化エラー時はユーザー向けメッセージを表示
- ログにはエラー種別、時刻、処理対象 ID を記録
- 削除失敗時は表示上の削除状態を巻き戻す

## 受け入れ条件

- [x] 本文必須でメモを作成できる
- [x] 対象日、タグ、カテゴリ、関連プロジェクトを設定できる
- [x] 既存メモの本文とメタ情報を更新できる
- [x] メモ削除後に一覧と検索結果から除外される
- [x] バリデーションエラー時に原因が項目単位で表示される
- [x] 他ユーザー所有メモの更新、削除が拒否される

## 確認方法

- 正常系: 作成、編集、削除を手動で実行
- 異常系: 空本文、不正日付、文字数超過で保存を実行
- 検索画面でタグ、対象日から再取得できることを確認
- 自動検証: `mise exec -- npm run test -w @nippo-local/api`
- 型検証/ビルド: `mise exec -- npm run typecheck -w @nippo-local/api`, `mise exec -- npm run build -w @nippo-local/web`
