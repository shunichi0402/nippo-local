# Spec: メモ・写真・録音から日報/月報を作る機能要件

## 背景

日々の作業では、あとで日報や月報にまとめたい情報が小さな単位で発生する。
たとえば作業メモ、気づき、出来事、写真、録音、文字起こしなどは、その場で残せないと失われやすい。

この仕様では、ローカル環境でそれらを蓄積し、必要な記録を見つけ、日報や月報に再利用できる状態を定義する。
実装方式を固定しすぎず、まずはユーザー体験、保存したい情報、MVP の境界を明確にする。

## 目的

- どの情報を入力、保存、検索、編集できる必要があるかを明確にする
- 写真、録音、文字起こしをどの範囲で扱うかを整理する
- 日報、月報生成に必要な集計、抽出、編集フローを定義する
- ローカル利用を前提にした保存、プライバシー、バックアップ方針を整理する
- MVP で実装する範囲と後続 Issue に分ける範囲を判断できるようにする

## 対象ユーザー

- 自分の作業内容や気づきを日々ローカル環境で記録したいユーザー
- 記録したメモ、写真、録音、文字起こしから日報や月報を作りたいユーザー
- 外部サービスに全ての記録を預けず、自分の端末上でデータを管理したいユーザー

## スコープ

### やること

- テキストメモ、写真、録音、文字起こしを記録として保存する
- 記録に日付、タグ、カテゴリ、関連プロジェクトなどのメタ情報を付与する
- 記録を日付別、タグ別、種類別、キーワードで探せるようにする
- 当日の記録から日報候補を抽出し、ユーザーが編集して Markdown として出力できるようにする
- 指定月の記録や日報から月報候補を作り、元記録へ戻れるようにする
- ローカル保存、バックアップ、プライバシー、外部 API 利用時の注意点を定義する

### やらないこと

- 複数ユーザーでの共同編集
- クラウド同期を必須にしたデータ管理
- 外部カレンダー、タスク管理、勤怠システムとの自動連携
- 写真や音声の高度な自動分類、顔認識、話者識別
- 生成された日報や月報を外部サービスへ自動投稿する機能

## ユースケース

1. ユーザーは作業中に気づいたこと、作業メモ、出来事をすぐに記録する
2. ユーザーは写真をアップロードし、メモに添付して文脈を残す
3. ユーザーは会話や思考メモを録音し、必要に応じて文字起こしを保存する
4. ユーザーは当日の記録を見返し、日報の下書きを作成する
5. ユーザーは指定月の記録や日報を集約し、月報の下書きを作成する

## 機能要件

### 記録の基本データ

記録は、テキスト、写真、音声、文字起こしをひとまとまりで扱える単位とする。

保存する主な項目:

- ID
- 作成日時
- 更新日時
- 対象日
- タイトル
- 本文
- 種類
- タグ
- カテゴリ
- 関連プロジェクト
- 添付ファイル一覧
- 文字起こし本文
- 日報または月報で利用済みかどうか
- 元記録への参照

種類の例:

- memo
- photo
- audio
- transcript
- daily_report
- monthly_report

### テキストメモ

ユーザーはテキストメモを作成、編集、削除できる。
メモ本文は Markdown を許容し、日報や月報へ転記しやすい形式で保存する。

必須要件:

- 本文を保存できる
- 対象日を設定できる
- タグ、カテゴリ、関連プロジェクトを付与できる
- 後から内容とメタ情報を編集できる
- 削除時は添付ファイルとの関係を確認できる

### 写真

ユーザーは写真ファイルを記録に添付できる。
写真はローカルの添付ファイルとして保存し、記録本文から参照できる。

必須要件:

- 写真ファイルをアップロードできる
- 添付した写真をプレビューできる
- 写真に説明文を付与できる
- 写真を記録から削除できる
- 削除時にファイル本体を消すか、参照だけ外すかを判別できる

MVP では、画像編集や自動補正は扱わない。

### 録音

ユーザーは音声を録音し、音声ファイルとして保存できる。
保存した音声は後から再生でき、必要に応じて文字起こしの元データとして扱う。

必須要件:

- 録音を開始、停止できる
- 音声ファイルを保存できる
- 保存済み音声を再生できる
- 音声にタイトル、対象日、タグを付与できる
- 音声ファイルの保存場所を記録から参照できる

MVP では、音声編集、ノイズ除去、話者識別は扱わない。

### 文字起こし

ユーザーは録音内容の文字起こし結果を保存、編集できる。
文字起こしは手動入力、外部 API、ローカルモデルのいずれでも登録できるようにする。

必須要件:

- 音声記録に文字起こし本文を関連付けられる
- 文字起こし本文を編集できる
- 文字起こしの作成方法を保存できる
- 文字起こしの作成日時を保存できる
- 元音声へ戻れる参照を保持する

文字起こしの作成方法:

- manual
- local_model
- external_api

外部 API を使う場合は、送信される音声やテキストの範囲をユーザーに明示する。

### 一覧と検索

ユーザーは保存した記録を見つけやすい形で一覧、検索できる。

必須要件:

- 日付別に表示できる
- タグ別に表示できる
- 種類別に表示できる
- キーワード検索できる
- 写真、音声、文字起こしを含む記録を検索対象にできる
- 検索結果から元記録を開ける

検索対象:

- タイトル
- 本文
- タグ
- カテゴリ
- 関連プロジェクト
- 写真の説明文
- 文字起こし本文

MVP では全文検索エンジンの高度なランキングは必須にしない。
単純な部分一致、日付、タグ、種類の絞り込みを優先する。

### 日報生成

ユーザーは当日の記録から日報の下書きを作成できる。
生成結果は自動確定せず、ユーザーが編集して保存する。

必須要件:

- 対象日を指定できる
- 対象日の記録を候補として抽出できる
- 候補を選択、除外できる
- 作業内容、気づき、課題、次のアクションに整理できる
- 生成結果をユーザーが編集できる
- Markdown として保存、出力できる
- 日報から元記録へ戻れる

日報の構成例:

- 日付
- 作業内容
- 気づき
- 課題
- 次のアクション
- 参照した記録

MVP では、自動要約の品質よりも、候補抽出、編集、Markdown 出力を優先する。

### 月報生成

ユーザーは指定月の記録や日報を集約し、月報の下書きを作成できる。
月報は日報よりも期間の振り返りに寄せた構成とする。

必須要件:

- 対象月を指定できる
- 指定月の記録と日報を抽出できる
- 主な成果、継続課題、学び、次月の予定に整理できる
- 生成結果をユーザーが編集できる
- Markdown として保存、出力できる
- 月報から元の日報または記録へ戻れる

月報の構成例:

- 対象月
- 主な成果
- 継続課題
- 学び
- 次月の予定
- 参照した日報
- 参照した記録

MVP では、月報は保存済み日報を主な入力にする。
日報がない日の記録も追加候補として参照できるようにする。

## 保存データと添付ファイル

### 保存方針

ローカル利用を前提に、メタデータと本文は検索しやすい構造で保存し、写真や音声はファイルとして分けて保存する。

推奨する保存単位:

- 記録メタデータ
- 記録本文
- 添付ファイル
- 生成済み日報
- 生成済み月報

保存場所の例:

```text
data/
  records/
  reports/
  attachments/
    images/
    audio/
  backups/
```

各記録は添付ファイルの相対パスを保持する。
ファイル移動やバックアップをしやすくするため、絶対パスに依存しない。

### バックアップ

最低限、ユーザーが `data/` 全体をコピーすれば復元できる構成にする。

必須要件:

- データと添付ファイルの保存場所を明示する
- バックアップ対象ディレクトリを明示する
- 書き込み中の破損を避ける
- 削除前に確認できる

MVP では、自動バックアップは必須にしない。
ただし、後続でバックアップ世代管理を追加できる構成にする。

### プライバシー

写真、音声、文字起こしには個人情報や機密情報が含まれる可能性がある。
ローカル保存を基本とし、外部 API を使う場合は明示的なユーザー操作を必要とする。

必須要件:

- ローカルに保存されるデータの場所を説明する
- 外部 API に送信されるデータの種類を説明する
- 外部 API 利用の有効/無効を選べる
- 外部 API を使わずに手動入力で運用できる
- 写真、音声、文字起こしを削除できる

## MVP 範囲

### 初期リリースで必須にする機能

- テキストメモの作成、編集、削除
- 写真の添付、プレビュー、削除
- 音声ファイルの保存、再生
- 文字起こし本文の手動保存、編集
- 日付、タグ、種類による一覧
- キーワード検索
- 当日の記録から日報下書きを作る
- 日報を編集して Markdown で保存、出力する
- 指定月の日報から月報下書きを作る
- 月報を編集して Markdown で保存、出力する
- 元記録への参照
- ローカル保存場所とバックアップ対象の明示

### 後続 Issue に分ける機能

- ブラウザまたはネイティブ機能を使った録音 UI
- ローカルモデルによる文字起こし
- 外部 API による文字起こし
- 外部 API による日報、月報の要約補助
- 自動バックアップと世代管理
- 添付ファイルの容量表示と整理
- 高度な全文検索
- カレンダー表示
- 外部サービスへの投稿、エクスポート

### 未決定事項

- メタデータの保存形式を JSON、SQLite、Markdown front matter のどれにするか
- 添付ファイル ID とファイル名の命名規則
- 録音をアプリ内で行うか、外部で作った音声ファイルの取り込みから始めるか
- 外部 API を使う場合の対象サービスと設定方法
- 日報、月報テンプレートをユーザーが編集できるようにするか
